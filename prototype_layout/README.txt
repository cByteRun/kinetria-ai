IdeaRoute — от идеи к результату

ОТКРЫТЬ МАКЕТ
Дважды откройте IdeaRoute.html в современном браузере. Это самостоятельный HTML:
Tailwind CSS v4.3.5, Manrope с кириллицей, иконки и сценарии включены внутрь файла.
Подключение к интернету, установка пакетов и сборка не нужны.

Альтернативный вариант: index.html и файлы рядом с ним.
Локальный предпросмотр: node serve.cjs → http://127.0.0.1:4178
Сервер слушает только локальный адрес компьютера и обслуживает только эту папку.

РОЛИ
В правом верхнем углу — переключатель трёх ролей из ТЗ.
Сотрудник: свои обращения, создание, ответ на уточнение, просмотр решения.
Руководитель: обращения своего направления, ответственный, приоритет, сроки,
комментарии, уточнения, решения, выполненные действия, аналитика.
Администратор: общий реестр, категории, маршруты, резервная очередь и настройки.
«Ответственный» — назначение внутри процесса, а не четвёртая пользовательская роль.

СКВОЗНОЙ СЦЕНАРИЙ
1. Сотрудник → Новое обращение → Заполнить пример → Зарегистрировать.
2. Руководитель → Операционные процессы → Обращения → новая карточка.
3. Взять на рассмотрение → Запросить уточнение.
4. Сотрудник → карточка → ответить на уточнение.
5. Руководитель → Зафиксировать решение → Передать в работу, указать действия.
6. После выполнения → Зафиксировать решение → Реализовано, описать сделанное.
7. Сотрудник → Уведомления → результат → Ознакомился с результатом.
Мотивированный отказ также завершает цикл. Передача в работу — не завершение.

ИСКЛЮЧЕНИЯ
Категория «Другое» или неактивное правило → резервная очередь администратора.
Карточка A-020 изначально демонстрирует отсутствие правила.
Просрочки видны в обзоре и фильтрах реестра.
Поиск: номер, тема, описание, категория, решение, ответственный.
Есть фильтры по категории, подразделению, статусу и сроку; таблица и доска.
Вложения: до 3 файлов по 1 МБ, локально в браузере. Экспорт: текущая выборка в CSV.

СООТВЕТСТВИЕ ИСТОЧНИКАМ
Основной источник — DOCX ТЗ в docs/TZ: §2.2 роли; §2.3 основной сценарий;
§2.4 функции; §2.5 процесс и предотвращение потерь; §2.6 доступ; §2.7 аналитика;
§3.2 интерактивность; §3.5 демонстрационные данные; §3.6 дальнейшее развитие.
Business Vision: обращение → категория → маршрут → рассмотрение → решение →
обратная связь → аналитика. На первом плане ответственность и результат.
Полная карта покрытия доступна прямо в макете: «Как устроен маршрут».

ДАННЫЕ И ОГРАНИЧЕНИЯ
Исходные 20 синтетических обращений взяты из docs/TZ/Датасет.docx.
Заголовки сокращены для интерфейса. Исходные тексты, типы и статусы сохранены.
Даты, направления, сроки, события, связи и резерв A-020 добавлены для демонстрации.
Дата демонстрации фиксирована: 12 ноября 2026. Сроки — календарные дни.
Показатели рассчитываются по видимым карточкам; целевые KPI не выдуманы.
Хранение — localStorage текущего браузера. Это не защищённое хранилище.
Переключатель ролей демонстрирует UX прав, но не является авторизацией.
Серверных проверок доступа, внешних уведомлений и реальных интеграций нет.
Клиентские обращения, NPS и опросы — следующий этап, не часть внутреннего MVP.
Для промышленной версии нужны серверная авторизация, проверка прав, база данных,
закрытое хранилище файлов, журнал аудита, очередь уведомлений и контроль сроков.

Для повторного показа: «Как устроен маршрут» → «Сбросить демо-данные».
Проверенные сценарии и визуальные исправления описаны в design-qa.md.
Основной проект приложения и его настройки не изменялись: все файлы макета в tmp/maket.
