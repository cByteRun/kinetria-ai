# Telegram: UX-гайд и дерево навигации

Контракт интерфейса после ревью webhook, 12.11.2026. Основание: [Business Vision](BUSINESS_VISION.md), [сценарий №3](VALIDATION.md#-сценарий-3--telegram-closed-loop), [сущности дашборда](09-dashboard-spec.md). Название в интерфейсе — **IdeaRoute**, как в Business Vision (упоминание Idea Road в задании не означает переименование).

## Правила интерфейса

- Описание программы — только на главной `/start`, `/home`, `menu:home`. Первый `/start` непривязанного демопользователя включает вводную перед выбором аккаунта.
- `/help` объясняет сквозные сценарии и действия текущей роли; эмодзи служат визуальными якорями. Команды главной/помощи перечисляются по одной строке `/команда — описание`.
- После переключения: «Выбрана роль», имя аккаунта, назначение роли, специфичные команды (сотрудник: `/new`, `/draft`; администратор: `/reserve`), «Главная». Общие `/list`, `/stats` доступны на главной и в помощи.
- Инлайн-переходы редактируют сообщение, на котором нажата кнопка. Цель редактирования изолирована на время update через AsyncLocalStorage. Текстовые команды и ответы на пользовательский ввод создают сообщение: ID пользовательского сообщения никогда не используется для редактирования.
- Если сообщение удалено или Telegram запрещает его редактировать, создаётся новое. Неизменившийся текст считается успехом. Сеть, 429, 5xx и другие ошибки не маскируются новой отправкой: webhook остаётся повторяемым.
- Текст длиннее 3800 UTF-16 единиц отправляется частями без обрезки и разрыва surrogate pair; кнопки только после последней части. Длинные карточки/история — исключение из редактирования, чтобы сохранить полный контекст.
- Главная, помощь, выбор демоаккаунта не отменяют рабочий шаг. `/cancel` очищает текущий шаг вместе с черновиком; `/new` начинает новый ввод. `/unlink` отключает привязку. Демопереходы сохраняют отдельные состояния аккаунтов.

## Голосовое обращение

Перед записью бот просит назвать «Проблема»/«Предложение» и категорию из действующего справочника, затем факты и ожидаемый результат. Лимиты: 120 секунд / 3 МиБ; аудио передаётся в Groq.

Предпросмотр содержит отдельные блоки:

```text
Черновик обращения — ещё не отправлен

Тема: …

Текст обращения
<полная расшифровка или введённый текст>

Метаданные
Тип: Проблема / Предложение
Категория: <название из справочника либо просьба выбрать>
Теги: … / не указаны
Предлагаемое решение: … / не указано
Вложения: N/3

Проверьте текст, тип и категорию…
```

Служебное оформление карточки без эмодзи, исходный текст автора сохраняется буквально. AI не меняет исходное описание. При сбое AI используется ручной черновик с исходным текстом, типом «Проблема» по умолчанию и незаполненной категорией; бот отдельно сообщает о необходимости ручной проверки. Неопределённая категория блокирует отправку.

Единственное действие регистрации — «✅ Подтвердить и отправить». «Изменить тип» открывает явный выбор двух значений, а не скрытое переключение. «Изменить категорию» показывает справочник. Редакторы темы/текста/решения/тегов принимают текст или голос; `-` очищает решение/теги. Предлагаемое решение до подачи — предложение автора, не итоговое решение ответственного.

«Записать заново» переводит в ввод, сохраняя старый черновик до успешного нового сообщения. Сбой Whisper не уничтожает его; «⬅️ Назад» или `/draft` возвращает карточку. Успешная новая запись заменяет текст и метаданные, очищает прежние вложения и выдаёт новый ключ подтверждения. Об этом бот предупреждает до записи. Старое подтверждение не регистрирует новый черновик.

Соответствие дашборду: `title`, `description`, `kind` (`problem`/`idea`), `category` (ID справочника), `tags`, `proposal`, вложения. Теги — до 8 по 48 символов, тематические, через запятую при ручном вводе; используются общими правилами повторяющихся тем. Владелец, срок, статус и история появляются в общей записи после регистрации. Тип `praise`, приоритет и тональность не добавлены в Telegram-редакторы этой задачей.

## Navigation Tree

Пути ниже — логические экраны бота, а не HTTP endpoints. `menu:*` вызывает ту же ветку, что команда.

```text
/ (private chat only)
├─ /start [token] → привязка → /home
├─ /start, /home, menu:home → главная текущего аккаунта
│  ├─ /help, help → сценарии + инструкция текущей роли → Главная
│  ├─ /login, demoMenu [gate + allowlist]
│  │  └─ demo:<account> → экран выбранной роли → menu:home
│  ├─ /new, menu:new [employee] → compose: инструкция + голос/текст
│  │  └─ успешное распознавание / текст → draft
│  │     ├─ category → список → cat:<index> → draft
│  │     ├─ kind → выбор → kind:problem / kind:idea → draft
│  │     ├─ edit:title / description / proposal / tags → edit
│  │     │  └─ исправленный текст/голос → draft
│  │     ├─ attach → ожидание документа/фото → проверка лимитов → draft
│  │     │  └─ ⬅️ Назад → menu:draft (без добавления файла)
│  │     ├─ rewrite → compose (старый черновик доступен через /draft)
│  │     ├─ submit:<key> → общая регистрация → R-номер
│  │     │  └─ open:<id> → detail
│  │     └─ cancel → очистка текущего шага
│  ├─ /draft, menu:draft [employee] → сохранённый draft / сообщение об отсутствии
│  ├─ /list, menu:list → список последних 10 → open:<id> → detail
│  ├─ /stats, menu:stats → сводка последних 30 → дашборд / Главная
│  └─ /reserve, menu:reserve [admin] → открытые без владельца → detail
├─ detail (доступ проверяет домен)
│  ├─ assign:<id> [manager; admin только резерв] → допустимые участники
│  │  └─ person:<key>:<id> → due (дата либо -) → confirmAssign
│  │     └─ confirmAssign:<key> → назначение + срок → detail
│  ├─ review:<status>:<id> [manager/handler, разрешённые переходы]
│  │  ├─ review → рассмотрение → detail
│  │  └─ clarification / in_progress / implemented / rejected / closed
│  │     └─ decision: вопрос / следующий шаг / решение → detail
│  ├─ reply:<id> [author, clarification] → текст ответа → review → detail
│  ├─ ack:<id> [author, итог] → сохранённое ознакомление
│  ├─ comment:<id> → текст комментария → detail
│  ├─ history:<id>[:offset] → история (8 событий)
│  │  ├─ Новее / Ранее → history с новым offset
│  │  └─ Открыть карточку → open:<id>
│  ├─ file:<id> → защищённая отправка файла
│  ├─ URL: дашборд → APP_URL/login
│  └─ Главная → menu:home
├─ /cancel, cancel → очистить шаг → подсказка /new, /list
└─ /unlink → отключить привязку
```

Кнопка «⬅️ Назад» в выборе типа/категории, текстовых редакторах, перезаписи и загрузке использует `menu:draft`: сбрасывает mode/field без изменения черновика. В назначении, сроке, подтверждении, комментарии и вводе решения/ответа возврат через `open:<id>` сбрасывает ожидание и открывает актуальную карточку. Кнопки главной и дашборда добавляются к спискам/сводке/помощи; URL скрывается при невалидном APP_URL. Непривязанный пользователь получает инструкцию привязки, занятый демоаккаунт — отказ без перехвата, конфликт версии — предложение открыть актуальный `/list`. Неизвестный ввод — подсказка `/home`, `/help`, `/cancel`.

## Роли и общий цикл

| Роль | Данные и ответственность |
|---|---|
| Сотрудник | Свои обращения, подача, ответ на уточнение, ознакомление |
| Ответственный | Только назначенные ему, рассмотрение и результат |
| Руководитель | Категории своего направления, назначение, рассмотрение и результат |
| Администратор | Общий реестр, резервное назначение; настройки в вебе, без публикации решения |

Сценарий №3: сотрудник подтверждает черновик → общий R-номер и безопасная карточка канала → руководитель назначает владельца/срок → ответственный уточняет, получает ответ, фиксирует шаг и решение → автор получает результат и отмечает ознакомление. Уведомление и ознакомление — разные факты. Смена демоаккаунта меняет реальную привязку к синтетическому профилю; одновременная адресная доставка нескольким ролям требует разных Telegram ID.

## Системное меню

`setup-telegram.mjs` регистрирует и сверяет через `getMyCommands`: `/start`, `/home`, `/help`, `/login`, `/new`, `/draft`, `/list`, `/stats`, `/reserve`, `/cancel`, `/unlink`. Это общий каталог команд, права проверяются отдельно. Демоалиасы не обходят gate/allowlist. Для применения каталога к живому боту после deployment: `pnpm telegram:webhook`; локальные изменения не означают автоматического обновления Telegram.

## Итерация: инструкция, вложения и меню

Инструкция показывает типы отдельной строкой, все категории действующего справочника списком, пять пунктов структуры и живой пример с категорией из этого справочника. Решение необязательно. Предпросмотр остаётся без декоративных эмодзи; все кнопки имеют эмодзи. Первые четыре ряда — редактирование и вложения, затем отдельный ряд подтверждения, затем перезапись/отмена.

`attach` сохраняет черновик и включает ожидание файла. Документы (включая DOC/DOCX/PDF) и фото принимаются также непосредственно в `draft`; во время редактирования текста файлы не меняют черновик. Лимиты — 3 × 1 МиБ; имена перечисляются в предпросмотре. Скачанные байты сохраняются в состоянии как base64, при подтверждении атомарно попадают в существующую `request_attachments` через общий submit_with_files. Новая миграция не нужна. `detail` показывает кнопки файлов, `file:<id>` повторно проверяет доступ к обращению и отправляет документ через Telegram. Наличие в приватном канале не даёт доступа к файлам.

Главная и `/help` объясняют назначение приватной ленты и её аудиторию: сотрудники, ответственные, руководители, администраторы. Фактическое членство каналом не проверяется.

Setup регистрирует каталог без дублей в `default` и `all_private_chats`, удаляет старые русские переопределения этих областей, сверяет оба каталога и вызывает `setChatMenuButton(type=commands)`. Основание: [Telegram Bot API](https://core.telegram.org/bots/api#setmycommands). Индивидуальные chat-scopes и другие языковые переопределения, заданные вне проекта, могут иметь приоритет; их требуется отдельно удалить при наличии. Для применения после deployment выполните `pnpm telegram:webhook`. Старые команды совместимы как тихие алиасы; публичная команда — `/login`.


## Qvin и темы: выход без команд (13.11.2026)

`/qvin` или «Спросить Qvin по реестру» → вопрос отдельным сообщением → ответ → следующий вопрос. «Ещё вопрос» сохраняет историю; «К реестру» открывает очередь; «Завершить диалог» очищает диалог и возвращает главную. При сбое модели «Повторить вопрос» повторяет сохранённый запрос. В подборе похожих обращений, группе, генерации и подтверждении удаления темы есть возврат к темам и/или главная; после сохранения, удаления, отмены и ошибок доступна главная. `/start` для выхода из этих экранов не нужен.

Сбой `Request unavailable` у администратора при старом DB-маршруте устраняется совместимым чтением через существующий авторизованный сервис тем; права Qvin остаются admin/manager. [Доказательства и границы](WORKSPACE-UPDATE.md#qvin-в-telegram-совместимость-и-возврат-13112026).
