# IdeaRoute · исправление регистрации в Vercel

## Доступ для жюри

[Открыть приложение](https://kinetria-ai.vercel.app) · [выбрать роль](https://kinetria-ai.vercel.app/login) · [инструкция и Telegram](JUDGES_GUIDE.md). Установка для просмотра не требуется.

## Причина «Не удалось сохранить. Повторите попытку»

13.11.2026 размещённая форма вызывала `public.submit_with_impact`, но подключённая production-БД не содержала функции, полей `origin`/`impact_hint`, таблиц портала и оценок эффекта. PostgREST возвращал **PGRST202**. Приложение сводило этот ответ к общему `saveError`, поэтому текст обращения и браузер не объясняли проблему. Таблицы AI-тем уже существовали: миграции оказались применены не в полном порядке.

## Исправление

- `scripts/migrate-product-expansion.mjs` применяет существующую `20261113014456_client_feedback_impact_qvin.sql` одной транзакцией и записывает её в migration ledger. При частично применённой схеме прерывается, не удаляя данные.
- Если темы уже установлены, обновляется `telegram_bridge_before_topics`; действующая внешняя обёртка тем не перезаписывается. Сравнение её определения до/после обязательно.
- Проверяются RLS трёх таблиц, отсутствие anonymous execute и прямого authenticated чтения приватных отзывов, права регистрации.
- Внутри savepoint выполняется синтетическая SQL-регистрация с откатом, затем обновляется PostgREST schema cache.
- Выполнен production deployment исправленного приложения со статусом READY. Runner запускался однократно в build-окружении нужного Vercel-проекта с его PostgreSQL-подключением. Секреты не извлекались в исходники или логи.
- Сервер теперь логирует только код ошибки регистрации. Для неподготовленного backend добавлено отдельное локализованное сообщение; форма сохраняет данные. Работающая регистрация не зависит от ответа AI.

Повторять runner после успешной миграции не требуется. Обычный запуск проекта использует SQL-миграции по порядку; этот runner предназначен для описанного случая уже установленной более поздней миграции. Для отдельного запуска нужен `pg@8.16.3` вне runtime-зависимостей приложения; путь задаёт `MIGRATION_PG_MODULE`, подключение — окружение Vercel. Не запускайте его с credentials другой БД.

## Фактическая проверка

**PASS, локальная PostgreSQL:** `node scripts/check-product-expansion-repair.mjs` воспроизводит отсутствие predecessor при сохранённых темах, применяет исправление, проверяет регистрацию/RLS/grants/неизменность wrapper и выполняет ROLLBACK.

**PASS, production браузер:** демовход сотрудника → ручная форма с небольшим файлом → сохранённый UUID → Drawer → скачивание и точное содержимое файла → reload → та же карточка у администратора. Портал фидбэков открывается, `/api/topics` отвечает HTTP 200. Первая попытка проверки прервалась сетевым `ERR_NETWORK_CHANGED` после успешного сохранения; проверка продолжилась по тому же UUID без повторного создания.

**PASS, Telegram read-only:** публичное имя бота соответствует ссылке жюри, webhook настроен, pending updates=0, authenticated probe подтверждает bot/Supabase ready; канал приватный, у бота есть post/edit. Whisper и текстовая модель доступны в каталоге Groq. Проверка не отправляла сообщения и не заменяет человеческую проверку голосового распознавания.

**PASS, локализация:** 1096 сообщений в каждом словаре RU/EN/KK, ICU/параметры/JSX — `check-i18n.mjs`. Подпись ROI больше не содержит встроенного русского текста в компоненте.

Корпоративные интеграции 1С/Битрикс24, CSAT/NPS и SSO остаются планом; исправление регистрации не меняет эти границы MVP. Экономический эффект демоданных не является результатом компании.
