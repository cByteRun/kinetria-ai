# Воспроизводимые E2E GIF · 13.11.2026

Записи создаются Playwright из текущего интерфейса IdeaRoute (айдентика Monogram IR — Dynamic Path). Источник — локальный браузер и работающая локальная Supabase, не смонтированные макеты экранов. Данные синтетические. [GIF и технический manifest](demos/manifest.json).

Telegram-стенд **не является web.telegram.org**. Он рендерит настоящие тексты и callback-кнопки обработчика и передаёт нажатия в настоящий webhook. Для доставки используется настоящий `delivery.ts` с SQL-адаптером Data API; граница Telegram API заменена сбором сообщений в браузере. Служебная карточка в канале обновляется, личное уведомление возвращается автору. Изменение статуса происходит в личном боте. SQL-транзакция Telegram откатывается по Ctrl+C; веб-сценарии оставляют явно синтетические записи в локальной БД.

## Подготовка

1. Выполнить локальный quick start из [README](../README.md#setup): Docker, Supabase, все миграции, аккаунты, четыре SQL seed. Настроить `.env.local` с демопаролем. Использовать исключительно изолированную локальную БД.
2. Установить Playwright/Chromium отдельно от runtime приложения, например `npm install --prefix /tmp/idearoute-recording playwright`, затем `node /tmp/idearoute-recording/node_modules/playwright/cli.js install chromium`; доступны overrides `PLAYWRIGHT_MODULE` (путь к `index.mjs`) и `PLAYWRIGHT_EXECUTABLE_PATH`.
3. Для кодирования установить Pillow и imageio-ffmpeg в отдельное Python-окружение. Зависимости записи не меняют приложение и lockfile.
4. Запустить `node scripts/start-demo-recording.cjs`. Скрипт читает **локальный** `supabase status -o json`, проверяет localhost и подставляет локальные API-ключи, не выводя их. При необходимости задать `SUPABASE_CLI` (полный путь). Next.js — порт 3016, build-dir `.next-demo`; настоящий токен Telegram отключён, AI — маркированный адаптер.

## Запись — строго последовательно

В отдельном терминале:

```sh
node scripts/record-demos.mjs
```

Веб-recorder проверяет ответы, сохранение и результат действий; поддерживает `DEMO_BASE_URL` (только localhost) и `DEMO_ONLY=1|2|3|5`. Сценарий 2 заранее создаёт отдельную синтетическую карточку через веб и затем проводит её один UUID через роли. Повтор прогона создаёт новые синтетические карточки.

**После завершения веб-записи**, запустить в другом терминале:

```sh
DEMO_TELEGRAM_SERVER=true node scripts/check-telegram-webhook-workflow.mjs
```

Он открывает `http://127.0.0.1:3018`, использует существующий локальный контейнер `supabase_db_modus_IDEA` (override `TELEGRAM_TEST_DB`). Его открытая SQL-транзакция может блокировать веб-изменения — параллельно веб-recorder не запускать. Записать:

```sh
node scripts/record-telegram-demo.mjs
```

Остановить Telegram-стенд Ctrl+C: выполняется ROLLBACK. Затем кодировать:

```sh
python3 scripts/encode-demo-gifs.py
```

При нестандартном Python-окружении задать `PYTHONPATH`, при готовом ffmpeg — `--ffmpeg /path/to/ffmpeg`. Записи сохраняются в игнорируемый `docs/evidence/demo-recording/`; окончательные GIF и `manifest.json` — в `docs/demos/`. Encoder: веб 1280 px / до 6 fps / 64 цвета; Telegram 1152 px / до 4 fps / 32 цвета, удаление визуально повторных кадров и отсутствие шумового dithering; действия замедлены recorder, ключевые элементы подсвечены, этапы подписаны. Manifest фиксирует размер, длительность и число кадров. Повреждённый GIF или меньше 10 кадров вызывает ошибку.
