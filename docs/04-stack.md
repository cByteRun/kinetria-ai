# 04 — Технологии и запуск

Для MVP используем Supabase CLI с SQL-миграциями, `supabase-js` для запросов к Data API и `supabase gen types` для типизации в Next.js. За полдня сборки этот подход даёт одну схему для данных и политик RLS, запросы с JWT пользователя и типы, сгенерированные из той же базы.

| Слой | Выбор | Назначение |
|---|---|---|
| Веб и API приложения | Next.js App Router и TypeScript | Экраны, серверная проверка входных данных и действия с обращениями |
| Аутентификация | Supabase Auth, `@supabase/ssr` и `@supabase/supabase-js` | Вход по email и паролю для заранее созданных тестовых аккаунтов. Права определяются профилем и ролью в БД |
| Хранение | Supabase PostgreSQL, Data API и Row Level Security (RLS) | Запросы через HTTPS с publishable key и JWT пользователя. RLS ограничивает доступ к строкам и при прямом обращении к API |
| Миграции | SQL в `supabase/migrations/`, Supabase CLI | Версионируем таблицы, индексы, роли доступа, политики RLS и функции для атомарных изменений |
| AI-черновик | Серверный вызов модели со структурированным ответом | Предлагает уточнение или черновик из сообщения. Сервер проверяет схему и категорию, интерфейс даёт автору править и подтвердить карточку |
| Вложения post-MVP | Приватный Supabase Storage | Тестовые файлы с проверкой доступа к обращению |
| Проверка | Браузерные сценарии и проверки прямого Data API | Контроль переходов, повторной отправки, доступа к чужой карточке и публикации итога |

## Стартер и структура приложения

Одно Next.js-приложение использует SSR-подход из официального `with-supabase`. В `lib/supabase/` находятся клиенты для браузера и сервера, `proxy.ts` обновляет сессию. Лендинг и кабинеты — страницы App Router, серверный вход — Server Action. Supabase хранит профили, а затем и обращения. [Исходники шаблона](https://github.com/vercel/next.js/tree/canary/examples/with-supabase)

Интерфейс локализован через `next-intl` без языковых префиксов в URL. Светлая и тёмная темы задаются общими CSS-стилями. Язык и тема сохраняются в cookie и применяются при серверной отрисовке.

В текущем локальном демо Supabase не требуется. Инструкция ниже относится к проверке подключённого Supabase Auth и к выбранному ранее варианту серверного хранения. По §3.3 ТЗ можно выбрать другое хранилище. Для локального MVP на одном сервере допустим SQLite с серверной проверкой доступа. Браузерное хранилище подходит для черновика или однобраузерного прототипа.

## SQL-миграции и подготовка демо

1. При необходимости инициализировать конфигурацию CLI через `supabase init`. Миграция профилей уже лежит в `supabase/migrations/`. Таблицы обращений и событий потребуют следующих миграций.
2. Привязать отдельный демопроект через `supabase link --project-ref <ref>`. Для актуальной версии CLI применить миграции через `supabase db push --remote`. Локальная проверка с `supabase start` и `supabase db reset` возможна при наличии Docker.
3. Завести тестовые аккаунты через Supabase Auth и загрузить синтетический набор с профилями и ролями. Хранить SQL для схемы и инструкции по подготовке демо в репозитории. Зафиксировать версии CLI, рантайма и зависимостей при реализации.
4. После применения миграций обновить типы базы командой `supabase gen types typescript --project-id <ref>` и передать тип `Database` в клиент `supabase-js`.
5. Для приложения задать `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Ключ с повышенными правами допускается в отдельном серверном скрипте подготовки аккаунтов. Обычные запросы приложения выполняются с JWT текущего пользователя.
6. Запустить Next.js локально или разместить приложение с доступом к демопроекту Supabase. Проверить вход под каждой ролью, сохранение истории и прямые обращения к Data API. В README указать зависимости от Supabase и модели, способ настройки серверного ключа, ручной режим подачи и запись сценария.

SQL-миграции меняют схему через CLI. Рабочие запросы приложения идут через Data API. На первом этапе доступны лендинг и кабинеты с синтетическими данными. Инструкция по локальному запуску и подключению Supabase Auth находится в [README](../README.md). [Руководство Supabase по миграциям](https://supabase.com/docs/guides/deployment/database-migrations)
