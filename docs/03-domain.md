# 03 — Доменные правила и контрольные примеры

## Регистрация

AI предлагает тип, категорию и описание в черновике. Обращение появляется в воронке после подтверждения автором. Назначение определяется проверенной категорией и правилами маршрутизации. Связывание повторов сохраняет исходные карточки и видимые итоги. Вес темы — число уникальных авторов в связанных карточках, доступных руководителю.

## Назначение и сроки

Реализованный MVP использует одну общую очередь. Начальный маршрут задаётся по категории, а отсутствие активного назначенного пользователя переводит новые обращения в резерв. Смена назначения руководителем записывается в историю. Уведомления, сроки и автоматическое переназначение уже открытых карточек при деактивации ответственного относятся к развитию.

Категория определяет очередь и владельца. Активный владелец должен иметь доступ к очереди. При пропуске правила, отсутствии или деактивации владельца карточка получает признак «Без владельца» и попадает руководителю очереди либо в общую резервную очередь. Смена назначения фиксируется в истории, новый владелец получает уведомление. Деактивация владельца также возвращает его открытые карточки в очередь на назначение. Резервная очередь имеет владельца процесса.

Для демо сроки первого ответа и решения отсчитываются от регистрации в календарных часах. Высокий приоритет — 24/72 ч, средний — 48/120 ч, низкий — 72/168 ч. Сроки фиксируются при создании и продолжают идти при уточнении и переназначении. Просрочка первого ответа — срок наступил, ответа ещё нет. Просрочка решения — срок наступил, обращение открыто. Проверка идёт по UTC, в интерфейсе время показывается локально. Для пилота согласуются рабочий календарь, приоритеты, срок реакции и порядок эскалации.

## Статусы и переходы

| Из | В | Действие |
|---|---|---|
| Новое | На рассмотрении | Ответственный принимает обращение |
| На рассмотрении / В работе | Ожидает уточнения | Ответственный публикует вопрос, автор получает уведомление |
| Ожидает уточнения | На рассмотрении | Автор отвечает, владелец получает уведомление |
| На рассмотрении | В работе | Ответственный фиксирует следующий шаг |
| На рассмотрении / В работе | Реализовано / Отклонено / Закрыто | Ответственный публикует содержательный итог. Для отказа требуется причина, для реализации — описание результата. «Закрыто» подходит для отзывов и других обращений с объяснением завершения |
| Любой открытый | Тот же статус | Руководитель назначает или меняет владельца, сервер фиксирует событие |

Три итоговых статуса терминальные. Первый содержательный ответ — первое адресованное автору сообщение ответственного или руководителя, включая уточнение и итог. Регистрация, автоназначение и техническая смена статуса его не устанавливают. При отсутствии ответа в сводке показывается число ожидающих отдельно. Доля завершённых считается по дате создания когорты, момент снимка фиксируется. Счётчик реализованных улучшений использует дату публикации итога и первичный ID связанной группы для дедупликации.

## Контрольные примеры

| Вход | Ожидаемый результат |
|---|---|
| Подтверждённый AI-черновик по мотивам A-003 | До подтверждения записи в очереди нет. После подтверждения назначается владельцу номенклатуры. Он запрашивает пример, автор отвечает, решение появляется в карточке. Повторная отправка с тем же ключом возвращает один номер |
| A-011, владелец не задан, срок первого ответа прошёл | Запись есть в резервной очереди и фильтре просрочек. После ручного назначения исходный срок сохраняется |
| A-017, попытка отклонить без причины | Сервер отклоняет действие, статус и история не меняются. С причиной автор видит итог и уведомление |
| A-018, положительный отзыв | Можно завершить с пояснением, счётчик реализованных улучшений не растёт |
| A-003 и второе синтетическое обращение о том же изделии | Руководитель связывает карточки, у каждого автора свой статус и ответ. Чужой номер и текст в карточке автора скрыты |
| Чужая карточка или вложение по прямой ссылке | Недоступны сотруднику. Сводка руководителя ограничена его очередями |
| Два действия с одной версией | Первое фиксируется, второе получает 409 и перечитывает карточку |

Для демо исходные 20 записей загружаются с номерами A-001…A-020. Импорт добавляет синтетические события регистрации и, где применимо, рассмотрения. Четыре терминальные записи получают синтетические итоги. Тест на 20% завершённых выполняется сразу после импорта, до добавления новых записей для показа.
