## Две независимые оси

`<html data-color-theme="blue" data-theme="dark">`: `data-color-theme` задаёт фирменную палитру (`blue` по умолчанию, `purple` — прежние фиолетовые/зелёные оттенки), `data-theme` сохраняет существующий светлый/тёмный режим. По умолчанию режим остаётся тёмным, как до интеграции. Выбор палитры сохраняется на год в cookie `idearoute_color_theme`, читается сервером до выдачи HTML и действует при навигации и перезагрузке. Неизвестное значение даёт blue. Изменение DOM без cookie — временный предпросмотр:

```ts
document.documentElement.dataset.colorTheme = 'purple'
```

Для постоянного выбора используйте `ColorThemeSelect` в Preferences. Палитра не меняет сессию или роль. Cookie светлого/тёмного режима и языка остаются прежними. Режим меняется через корневой `data-theme` немедленно; POST `/api/preferences/theme` сохраняет HttpOnly-cookie без RSC-refresh. При ошибке DOM и кнопка откатываются. Сервер передаёт текущую палитру в переключатель: первоначального эффекта синхронизации с DOM нет.

## Контракт пакета

Семантические токены: `--primary`, `--secondary`, `--accent`, `--page`, `--panel`, `--panel-tint`, `--text`, `--text-muted`, `--border`, `--on-primary`, `--primary-hover`, `--primary-active`. Градиенты: `--gradient-button`, `--gradient-background`, `--gradient-text`, `--gradient-glow`. Шкалы `--brand-50…900` питают утилиты лендинга. Нейтральные шкалы и статусы переопределяются в тёмном режиме.

Оттенки прежних CSS централизованы как `--color-*` в том же файле; локальные `--brand`, `--entry-brand`, `--hub-primary` и прочие существующие имена ссылаются на них. Это совместимость с плотным кабинетом, без цветовых литералов в его стилях. В purple сохранены исходные значения, в blue фиолетовые оттенки преобразованы в синюю гамму. Новые компоненты должны использовать семантические имена, а не добавлять `--color-*`.

Для нового пакета добавьте селектор `[data-color-theme="name"]`, определите семантические токены и шкалу brand; при необходимости переопределите совместимые оттенки. Затем добавьте значение в переключатель и серверную проверку cookie в layout. Все значения HEX/RGB определяются в `themes.css`; компоненты и SVG интерфейса используют переменные/currentColor. Статический SVG/PNG и favicon имеют фиксированный синий цвет для внешних потребителей.

## Типографика и геометрия

Из источника взяты Inter (основной), Onest (заголовки), JetBrains Mono (номера/метаданные); подключения глобальные через `app/fonts.ts` и `next/font/local`, с metric-adjusted fallback. Локальные variable WOFF2 и лицензии OFL находятся в `public/fonts/`; исходники — Google Fonts google/fonts. Поднабор сохраняет латиницу, кириллицу (включая KK), пунктуацию и символы; Inter использует исходную оптическую ось 14. Mono загружается по использованию, без preload. Внешнего CSS Google Fonts нет. Веса: 400/500/600, дополнительно 700 для существующего кабинета. Тело лендинга: 16 px / 1.5, вводный текст 18 px / 1.6, H1 36/48/56 px / 1.15 по ширине, H2 30/36 px / 1.2, tracking заголовков −0.02em, метаданные 12 px. Вход и кабинет используют те же семейства с существующей плотностью рабочих таблиц.

Секции: вертикальные отступы 80/112 px, горизонтальные 24/32 px, контейнер 1280 px; карточки 20–32 px, радиусы 6 px у действий и 12/16 px у карточек. Геометрия плавающих панелей кабинета сохранена. Мобильная шапка переносит настройки; иллюстративный реестр упрощён на узких экранах. Уважение `prefers-reduced-motion` распространяется на CSS и автоматическую смену этапов.

## Обновление CSS

`pnpm styles:landing` пересобирает `app/new-landing.css` закреплённым Tailwind 3.4.17 (первый запуск требует npm-сети). Сгенерированный CSS хранится в Git: обычные dev/build не требуют Tailwind или Vite. Утилиты ограничены `.new-landing` и не меняют кабинет. Цвета берутся из переменных общего пакета.

`tmp` и `prototype_layout` исключены из TypeScript Next-приложения: это отдельные исходники Vite, не рабочие маршруты. Для параллельной локальной проверки можно задать `IDEAROUTE_BUILD_DIR=.next-brand`; обычный каталог `.next` остаётся по умолчанию.

## Концепции логотипа IdeaRoute

В [галерее концепций](../brand-assets/preview.html) можно сравнить три варианта на светлом, тёмном и сетчатом фоне, переключить знак в макете шапки лендинга и выбрать фавикон для вкладки браузера. Концепции используют индиго из брифа. Действующие файлы айдентики продукта перечислены в таблице выше.

| Вариант | Знак | Шрифтовая часть |
| --- | --- | --- |
| Precision Node Route | Сквиркл, два узла и штрихи статуса | Inter 600, раздельные цвета Idea и Route |
| Closed-Loop Spark | Петля возврата со стрелкой и искрой | Manrope 700 |
| Monogram IR — Dynamic Path | Пин и монограмма с восходящим маршрутом | Onest 600, трекинг +0.04em |

В каждой папке `brand-assets/variant-*` находятся `icon.svg`, `logo-full.svg` и тематические `icon-light.svg`, `icon-dark.svg`, `logo-light.svg`, `logo-dark.svg`. Файлы без суффикса темы используют светлую палитру. У знаков `viewBox="0 0 48 48"`, у надписи — векторные контуры локальных шрифтов.

Знак и полный логотип экспортируются в PNG 512 × 512 и 1024 × 1024 для обеих тем. Полный логотип центрируется на прозрачном квадрате с сохранением пропорций. `favicon-16.png` и `favicon-32.png` предназначены для браузерной вкладки.

Для повторного экспорта из корня репозитория установите зависимости приложения командой `pnpm install --frozen-lockfile` и запустите генератор. Нужны Node.js, Python 3.12 и uv. Sharp берётся из зависимостей Next.js.

```sh
uv run --python 3.12 --with fonttools==4.68.0 --with brotli==1.2.1 python scripts/generate-brand-assets.py
```
