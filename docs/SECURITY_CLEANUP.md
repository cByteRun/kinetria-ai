# Очистка Git · 13.11.2026

Выполнено до обновления документации и GIF. Начальный скан охватил 1169 локальных объектов, включая недостижимые. Проверялись URI БД, ключи провайдеров, Telegram-токены, JWT, приватные ключи, приватные конфиги и совпадения с локальным окружением; дополнительно исследованы PostgreSQL user/password в исторических тестах.

Найдено: жёстко заданные локальные PostgreSQL user/password в двух тестах, hosted project reference и deployment IDs в трёх объектах. Значения в отчёте не публикуются. Реального удалённого пароля PostgreSQL в проверенных форматах не обнаружено. Тестовые пары также удалены по требованию задачи: используются `PGUSER`/`PGPASSWORD` с явной проверкой окружения; hosted migration guard использует `MIGRATION_PROJECT_REF`.

`git filter-repo --force --sensitive-data-removal --blob-callback …` переписал 14 из 40 коммитов. Выполнены `git reflog expire --expire=now --all` и `git gc --prune=now --aggressive`. По всем четырём удалённым фрагментам `git log --all -S …` вернул ноль коммитов. Повторный скан всех 1110 оставшихся локальных Git-объектов: 0 находок. Отслеживаемое рабочее дерево: 0 находок. Сканер дополнен запретом жёстко заданной тестовой пары.

Локальные `.env*` не удалялись: они игнорируются Git и нужны для запуска. Пустой `.env.example` хранит только имена переменных. «Рабочее дерево без секретов» в данном отчёте означает отслеживаемые исходники и артефакты, не локальное защищённое окружение.

Фоновый fetch во время работы вернул старую историю в remote-tracking refs. Поэтому локальная настройка `origin` удалена, reflog/GC повторены; повторный скан всех 1110 объектов снова чистый. Прежний адрес: `https://github.com/cByteRun/kinetria-ai.git`. Не подключать его с автоматическим fetch до очистки серверной истории: иначе старые секреты вернутся. После согласованной очистки удалённой стороны подключение можно восстановить через `git remote add origin <URL>`.

Удалённая история не перезаписывалась, force push не выполнялся. Очистка GitHub-кешей, форков и чужих клонов не подтверждена. Если опубликованный ключ действующий, его нужно отозвать: переписывание истории не меняет права доступа. После публикации очищенной истории участникам нужен свежий clone. Отчёт не гарантирует распознавание произвольных неизвестных секретов или текста внутри изображений.

Проверка: `python3 scripts/check-repository-security.py --history` и без `--history`. Сканер не выводит найденные значения.
