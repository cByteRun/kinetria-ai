# 06 — Рабочий процесс команды

Актуальный срез 13.11.2026: **IdeaRoute**. Qvin, сохраняемые AI-темы и клиентский портал Web/Telegram реализованы; CSAT/NPS, SSO, RAG и 1С/Б24 — план. [Единый статус и ограничения](TENDER_AUDIT.md) · [Шесть сценариев](../README.md#scenarios) · [Свежие записи](DEMO_RECORDING.md). Исторические результаты ниже относятся к указанным в них прогонам.

Начинаем с единого сценария по мотивам A-003. Дизайн, доменная логика и демоданные используют одни статусы и роли из [доменных правил](03-domain.md). Каждую функцию доводим до экрана и проверяем на тестовых ролях.

| Зона | Результат |
|---|---|
| Продукт и дизайн | Чат с предпросмотром, CRM-доска, тексты ошибок и карточка с итогом |
| Разработка | Миграции, API, доступ, журнал событий и рабочие экраны |
| Данные и проверка | Воспроизводимая загрузка синтетического набора, проверки переходов и контрольные сценарии |
| Защита | Прототип, материалы подачи, демодоступ, резервная запись и репетиция по таймеру |

Один участник может вести несколько зон. При изменении статуса, поля или права обновляем правила, пример данных и экран в одной задаче. Для каждой задачи фиксируем экран или действие, ожидаемый результат и способ проверки. Перед сборкой показываем изменение под реальной тестовой ролью и проверяем недоступность для чужой роли.

## Проверка перед демонстрацией

- Чистый запуск, миграции и импорт демоданных выполняются по инструкции.
- До подтверждения AI-черновика в CRM нет записи. Повтор отправки создаёт одну запись. Ошибка изменения оставляет прежний статус.
- Запись без владельца видна в очереди, просрочка фильтруется, назначение отражается в истории.
- Автор открывает уведомление, читает итог в карточке и отдельно подтверждает ознакомление.
- Другой автор не может открыть запись, события или файл. Руководитель видит только свои очереди.
- Сводка совпадает с контрольными числами до интерактивных изменений.
- Репетиция, ссылки и описание реализации соответствуют фактической сборке.

## Синхронизация и ревью

При изменении реализации сверяем историю коммитов и обновляем Business Vision, документы 00–09, roadmap, валидацию и README в одной задаче. Business Vision задаёт продуктовую цель; планы и работающие функции обозначаем отдельно. Официальные даты и непроверенные внешние факты без новых источников не изменяем.

Перед показом дополнительно проверяем ширины 320, 390, 768 и 1440 px, обе темы и сохранение выбора, читаемые подписи мобильной навигации, карточку реестра и раскрытие темы. Сотрудник/клиент не должны открывать аналитику прямой ссылкой. Для ответственного, руководителя и администратора числа вычисляются только по их доступным карточкам. Несколько тегов не удваивают общие KPI.

Коммит оформляем Conventional Commits от настроенного автора Git. Результат ревью и точные ограничения проверки: [CODE-REVIEW](CODE-REVIEW.md).

### Дополнительная приёмка входа и обратной связи

Проверяем вход → кабинет без ручного обновления → выход → прямой защищённый URL → вход. Проверяем неправильный пароль, состояние ожидания, обычную отправку без JavaScript и запрет чужого Origin. Не запускаем второй dev-сервер ради проверки.

Для карточки проверяем читаемость владельца, срока, решения и истории; на мобильном — закрепление панели при прокрутке и доступность последней кнопки над ней. В обеих темах проверяем обычное и hover-состояние результатов. В уведомлениях проверяем фильтры и различие между прочтением обновления и ознакомлением с решением.

### Приёмка локализации

Перед merge обязательны `node scripts/check-i18n.mjs` и `npx tsc --noEmit --noUnusedLocals`. Новая UI-строка добавляется одновременно в RU/EN/KK; переменные и множественные формы оформляются ICU. Коды БД не переводятся. Браузерный прогон проверяет смену языка без потери черновика, сохранение cookie после перезагрузки/выхода, все роли и отсутствие hydration/MISSING_MESSAGE ошибок. Не сохраняем уже переведённые подсказки в состоянии: храним ключ, переводим при рендере.

## CI и локальная DB/RLS-проверка · 13.11.2026

Supabase CLI `2.122.1` закреплён в devDependencies и lockfile. Установка: `pnpm install --frozen-lockfile`; Docker должен быть запущен. CLI вызывается через `pnpm exec supabase`; тестовый сервер также находит локальный бинарник без глобальной установки. В config убрана ссылка на отсутствующий seed.sql; синтетические данные подготавливаются явно.

```sh
pnpm test
pnpm exec tsc --noEmit --noUnusedLocals
pnpm build
pnpm db:start
pnpm db:migrate
pnpm test:db
pnpm dev:test
```

`test:db` берёт ключи только из локального `supabase status`, проверяет localhost у API/БД, создаёт девять демопрофилей и синтетические карточки/маршруты. SQL-проверки категорий, Telegram, параллельных демовходов и клиентской изоляции выполняются с BEGIN/ROLLBACK; фикстуры остаются в локальной БД. Пароль локальных демоаккаунтов задаётся `LOCAL_TEST_DEMO_PASSWORD` (по умолчанию `Local-ci-demo-123!`); `dev:test` использует тот же пароль и отключает внешние AI/Telegram. Это тестовый контур, не production.

Для отдельного чистого контура скопировать config и migrations в временный каталог, задать уникальные project_id и порты; `SUPABASE_WORKDIR=/absolute/path` поддержан обоими тестовыми runner. `SUPABASE_CLI` переопределяет путь бинарника. Не сбрасывать существующую БД: если схема менялась вручную, `migration up` может остановиться на уже существующей таблице.

GitHub workflow `.github/workflows/ci.yml` запускает TypeScript, i18n/модульные скрипты, production build и чистый Supabase с DB/RLS при push/PR. Hosted-ключи не нужны, миграции рабочих проектов не применяются.

## Персональный тур по роли · 13.11.2026

После входа кнопка в шапке показывает текущую роль, её цвет и бейдж «Индв.». `generateTourSteps(currentRole, currentRoute)` собирает шесть шагов по готовым компонентам «Обзора»: старт, метрики, очередь/создание, маршрут, фокус и результат. Сотрудник проходит создание → статус/уточнение → ознакомление; руководитель — рассмотрение/назначение → контроль результата; ответственный — уточнение/работа → письменный итог; администратор — общий мониторинг → резерв/владелец → возврат результата автору. Остальные функции предлагается изучить позже; 1С/Б24 остаются планом.

На лендинге и входе общий тур «Try in 3 minutes» объясняет четыре кабинета и их персональные гиды, затем общий Telegram-канал и мобильную работу в боте. В начале и финале можно опционально выбрать «Попробовать сквозной сценарий прямо сейчас»: прежний интерактивный учебный цикл в одном окне без входа. В финале также доступны выбор роли, канал и бот. В кабинетах тур подсвечивает настоящие виджеты текущей роли и не создаёт записи: после завершения пользователь выполняет действия обычными формами. Запуск из шапки и «Начать тур заново» открывает `?view=overview` текущей роли, сбрасывает номер шага и ожидает появления Overview после навигации. Скрытые/отсутствующие цели пропускаются либо заменяются резервной целью; для пустой очереди показывается инструкция без предложения открыть отсутствующую карточку. Тексты локализованы RU/EN/KK. [Архитектура и проверка](GUIDED-TOUR.md).
